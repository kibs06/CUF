# SoleVision — Product Architecture AI Context

> Condensed reference for AI agents working on the product system.
> Derived from codebase analysis (July 16, 2026).
> Optimized for implementing **product reviews and ratings**.

---

## Quick Facts

- **Stack:** Flutter + Supabase (Postgres, Storage, Realtime)
- **State management:** ChangeNotifier + Provider
- **Product ID type:** `TEXT` (UUID stored as text, not native UUID)
- **Storage bucket:** `product-images` (public read)
- **No reviews/ratings system exists yet** — this is a planned feature

## Database Schema (Product Tables)

### products
```sql
CREATE TABLE public.products (
  id              TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
  store_id        UUID REFERENCES public.stores(id),
  seller_id       UUID REFERENCES public.profiles(id),
  name            TEXT NOT NULL,
  description     TEXT,
  price           NUMERIC NOT NULL CHECK (price >= 0),
  category        TEXT NOT NULL DEFAULT 'General',
  tags            TEXT[] DEFAULT '{}',
  collection      TEXT,
  sku             TEXT,
  is_active       BOOLEAN NOT NULL DEFAULT true,
  is_featured     BOOLEAN NOT NULL DEFAULT false,
  is_published    BOOLEAN NOT NULL DEFAULT true,
  created_at      TIMESTAMPTZ DEFAULT now(),
  updated_at      TIMESTAMPTZ DEFAULT now()
);
```
**RLS:** Anyone can read. Sellers/Admins can insert/update/delete.

### product_images
```sql
CREATE TABLE public.product_images (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_id      TEXT REFERENCES public.products(id) ON DELETE CASCADE,
  image_url       TEXT NOT NULL,
  display_order   INTEGER NOT NULL DEFAULT 0,
  is_primary      BOOLEAN DEFAULT false
);
```
**RLS:** Anyone can read. Product owner/Admins can manage.

### product_variants (size × color combinations)
```sql
CREATE TABLE public.product_variants (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_id      TEXT REFERENCES public.products(id) ON DELETE CASCADE,
  size            TEXT NOT NULL,
  color           TEXT,
  stock           INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  additional_price NUMERIC NOT NULL DEFAULT 0 CHECK (additional_price >= 0),
  sku             TEXT
);
```
**RLS:** Anyone can read. Product owner/Admins can manage.

### inventory (aggregated stock by size)
```sql
CREATE TABLE public.inventory (
  product_id      TEXT REFERENCES public.products(id) ON DELETE CASCADE,
  size            TEXT NOT NULL,
  stock           INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  updated_at      TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (product_id, size)
);
```
**RLS:** Anyone can read. Product owner/Admins can manage.
**Note:** Inventory is synced from product_variants via `_syncInventoryFromVariants()`. One row per unique size, stock summed across all colors.

### product_customizations
```sql
CREATE TABLE public.product_customizations (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_id      TEXT REFERENCES public.products(id) ON DELETE CASCADE,
  option_name     TEXT NOT NULL,
  option_type     TEXT NOT NULL DEFAULT 'text' CHECK (option_type IN ('text', 'select', 'color')),
  options         TEXT[] DEFAULT '{}',
  is_required     BOOLEAN DEFAULT false,
  additional_price NUMERIC NOT NULL DEFAULT 0
);
```

## How Products Are Fetched (Customer Side)

```sql
-- SupabaseService.fetchProducts()
SELECT *,
  stores(name),
  product_images(image_url, display_order),
  inventory(size, stock),
  product_variants(size, stock)
FROM products
WHERE is_active = true
ORDER BY created_at DESC;
```

**Important:** `SupabaseService._mapProduct()` transforms the raw joined result into the UI format:
- Flattens `product_images` into an `images` list of URL strings
- Extracts `store_name` from the `stores` join
- Normalizes price to `double`
- Returns a `Map<String, dynamic>` (not a typed model)

Final shape:
```dart
{
  'id': 'uuid',
  'name': 'Carcar Heritage Oxford',
  'price': 1299.0,
  'category': 'Formal',
  'store_id': 'uuid',
  'store_name': 'Valladolid Leather Co.',
  'images': ['url1', 'url2'],  // flattened by _mapProduct()
  'product_images': [{'image_url': 'url1', 'display_order': 0}, ...],
  'inventory': [{'size': '8', 'stock': 10}, ...],
  'product_variants': [{'size': '8', 'color': 'Black', 'stock': 5}, ...],
}
```

## Size Resolution (Critical Pattern)

The customer size selector merges data from **two sources**:

```dart
// ProductDetailScreen._buildSizesMap()
Map<String, int> _buildSizesMap() {
  final Map<String, int> sizes = {};

  // 1. From inventory table (aggregated per size)
  for (final row in inventory) {
    sizes[size] = (sizes[size] ?? 0) + stock;
  }

  // 2. From product_variants table (per size+color)
  for (final row in variants) {
    // Take the higher stock value if size already exists
    sizes[size] = (sizes[size]! < stock) ? stock : sizes[size]!;
  }

  // 3. Sort numerically by EU size
  // ...
}
```

**Why two sources?** Inventory is the "source of truth" for stock display, but variants provide per-color stock. The higher value wins.

## Image Upload Flow

```
1. Seller picks images via ImagePicker
2. ProductService._uploadImages() uploads to Supabase Storage
   - Bucket: 'product-images'
   - Path: '{sellerId}/{productId}/{timestamp}_{index}.{ext}'
3. Returns public URLs
4. Inserted into product_images table with display_order
5. First image is marked is_primary = true
```

**Storage bucket:** `product-images` (must be set to PUBLIC in Supabase Dashboard)

## Inventory Sync Pattern

When variants are created/updated, inventory is automatically synced:

```
ProductService._syncInventoryFromVariants(productId, variants)
  1. Group variants by size → sum stock across all colors
  2. Delete existing inventory rows for this product
  3. Insert one row per unique size with aggregated stock
  4. Fire low_stock notification if any size ≤ 5
```

**Called by:** `createProduct()`, `updateProduct()`, and `syncProductActiveStatus()`

## Existing Product Data Model

Products are stored as `Map<String, dynamic>` (not a typed model). Key fields:

```dart
{
  'id': String,                    // TEXT (UUID as string)
  'store_id': String,              // UUID
  'seller_id': String,             // UUID
  'name': String,
  'description': String?,
  'price': num,                    // int or double from Supabase
  'category': String,              // 'Casual', 'Formal', 'Sports', 'Sandals', 'Custom', 'Other'
  'tags': List<String>,
  'is_active': bool,
  'is_featured': bool,
  'created_at': String,            // ISO 8601
  'updated_at': String,            // ISO 8601
  // Joined fields:
  'store_name': String?,           // from stores(name)
  'images': List<String>,          // flattened image URLs
  'product_images': List<Map>,     // raw joined images
  'inventory': List<Map>,          // [{size, stock}, ...]
  'product_variants': List<Map>,   // [{size, color, stock, additional_price}, ...]
  'product_customizations': List<Map>,
}
```

## Reviews & Ratings — Where to Add

**No reviews system exists.** To implement it, you would need:

### New Database Tables
```sql
-- product_reviews
CREATE TABLE public.product_reviews (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_id      TEXT REFERENCES public.products(id) ON DELETE CASCADE,
  customer_id     UUID REFERENCES public.profiles(id) ON DELETE CASCADE,
  order_id        BIGINT REFERENCES public.orders(id) ON DELETE SET NULL,
  rating          INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
  title           TEXT,
  body            TEXT,
  is_verified      BOOLEAN DEFAULT false,  -- purchased = true
  created_at      TIMESTAMPTZ DEFAULT now(),
  UNIQUE(product_id, customer_id)  -- one review per product per customer
);

-- product_review_images (optional)
CREATE TABLE public.product_review_images (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  review_id       BIGINT REFERENCES public.product_reviews(id) ON DELETE CASCADE,
  image_url       TEXT NOT NULL,
  display_order   INTEGER DEFAULT 0
);
```

### Suggested RLS Policies
```sql
-- Anyone can read reviews
CREATE POLICY "Reviews are viewable by everyone"
  ON product_reviews FOR SELECT USING (true);

-- Customers can insert reviews for products they purchased
CREATE POLICY "Customers can insert reviews"
  ON product_reviews FOR INSERT
  WITH CHECK (
    auth.uid() = customer_id
    AND EXISTS (
      SELECT 1 FROM order_items oi
      JOIN orders o ON o.id = oi.order_id
      WHERE o.customer_id = auth.uid()
      AND oi.product_id = product_id
    )
  );

-- Customers can update/delete their own reviews
CREATE POLICY "Customers can update own reviews"
  ON product_reviews FOR UPDATE USING (auth.uid() = customer_id);
CREATE POLICY "Customers can delete own reviews"
  ON product_reviews FOR DELETE USING (auth.uid() = customer_id);
```

## Patterns to Follow

1. **Products as Maps** — Products are `Map<String, dynamic>`, not typed models (except variants/customizations)
2. **Singleton services** — `static final ProductService instance = ProductService._()`
3. **Inventory is aggregated** — One row per size, stock summed across colors
4. **Image upload to Storage** — Public bucket, path: `{sellerId}/{productId}/{timestamp}_{index}`
5. **Cascade deletes** — Deleting a product removes images, variants, inventory, customizations
6. **RLS everywhere** — All tables have Row Level Security
7. **Optimistic updates** — Update local state first, sync in background
8. **Price as num** — Supabase returns `int` for whole numbers, `double` for decimals — always cast via `(x as num?)?.toDouble()`
